# Owl 管理平台 UI 升级设计规格

## 目标

在不改变现有业务接口、权限、脱敏和数据提交契约的前提下，将后台升级为一套更成熟的中国大陆企业管理平台视觉系统：使用轻量浅色侧栏、科技蓝品牌色、淡蓝灰工作区、清晰的信息密度，以及统一的列表、表格和 Dialog 结构。

## 范围

本轮采用“全局壳层升级 + 兼容型列表变体 + 用户管理试点”。

### 本轮包含

- 默认浅色主题的蓝灰色彩系统，以及相匹配的深色主题。
- 已认证后台的主布局、轻量侧栏和顶栏视觉升级。
- `SearchFilter`、`DataTable`、`Pagination`、`Badge`、`Dialog` 的兼容型新外观，不破坏原有调用方式。
- 用户管理页的页面标题、操作区、搜索工具栏、表格、分页和状态表现。
- 用户新增/编辑 Dialog 的分组、滚动区域、固定操作区和响应式排布。
- 1440px 桌面视口的视觉对照与核心交互验证。

### 本轮不包含

- 不新增后端接口、数据库字段或用户头像字段。
- 不展示当前接口或页面没有接入的伪筛选、伪排序、伪批量操作或伪环境切换。
- 不一次性逐页重构全部后台页面；共享壳层会全局生效，列表变体先由用户管理页验证后再推广。
- 不重写认证、权限、脱敏、WebSocket、水印或通知逻辑。
- 不部署或发布生产环境。

## 设计原则

1. **颜色用于建立层级，而不是装饰。** 主蓝色用于导航选中、主操作、焦点、链接和选中行；绿色、橙色、红色只表达状态。
2. **简洁不等于空。** 使用紧凑但舒适的行高、完整分页、明确工具栏和连续工作区，让页面显得完整且在使用中。
3. **侧栏保持轻量。** 浅色背景、细分隔线、弱图标、分组标题和浅蓝选中态；禁止整块深色或高饱和背景。
4. **保留真实行为。** 参考图仅作为布局和视觉目标；现有功能契约优先于像素复刻。
5. **兼容优先。** 高频基础组件保留默认 API；新工作台外观通过可选 variant/prop 接入，降低对几十个消费者的回归风险。

## 视觉系统

### 浅色主题

- 页面背景：`#F4F7FB`
- 工作区/卡片：`#FFFFFF`
- 主文字：`#182230`
- 次文字：`#667085`
- 边框：`#E4EAF2`
- 主色：`#2563EB`
- 主色浅底：`#EEF4FF`
- 成功：`#12B76A`，浅底 `#ECFDF3`
- 警告：`#F79009`，浅底 `#FFFAEB`
- 危险：`#F04438`，浅底 `#FEF3F2`
- 侧栏背景：`#F8FAFD`
- 侧栏悬浮：`#F3F6FB`
- 侧栏选中：`#EEF4FF`

### 深色主题

深色主题使用深蓝灰而非纯黑：主背景约 `#0B1220`，工作区约 `#111A2B`，边框约 `#263247`，浅文字约 `#F2F4F7`。主题色仍保持蓝色，但提高亮度以满足暗背景对比度。

### 动态主题

系统现有蓝、绿、紫、橙、红、青主题继续可用。它们只覆盖品牌主色、焦点和图表色，不再把中性背景、边框和大面积工作区染成对应色。默认主题改为科技蓝，避免生产环境仍显示黑白灰。

## 应用壳层

### 已认证布局

- 修改真实入口 `frontend/app/(authenticated)/layout.js`，不以未使用的 `common-layout.jsx` 作为实现入口。
- 桌面侧栏从固定 256px 调整到 240px；主区保持自适应。
- 主内容使用淡蓝灰背景，桌面内边距 20px。
- 表格继续允许内部横向滚动，页面本身不产生横向滚动。

### 侧栏

- 使用 `sidebar-*` token，而不是通用 `card/primary` token。
- 品牌区保持白色/极浅蓝灰，不使用深色品牌块。
- 菜单项高度约 40px，左右 12px，圆角 8px。
- 普通项使用灰蓝图标和文字；hover 使用极浅蓝灰。
- 当前项使用浅蓝背景、主蓝图标和文字，并增加 3px 左侧强调线。
- 继续由后端菜单树驱动，不写死参考图中的菜单。
- 业务菜单与系统菜单使用现有数据分组；仅增加分组标题和留白，不改变展开/收起逻辑。

### 顶栏

- 高度由 64px 收紧到约 56px，使用白色背景和细底边。
- 保留主题切换、通知和用户菜单。
- 左侧仍显示真实欢迎信息；本轮不增加没有数据来源的全局搜索、环境切换或伪面包屑。
- 去除 Header 内未渲染的系统名称、Logo 状态及其重复配置请求；系统名称、Logo 和主题配置继续由 Sidebar 的现有请求负责。

## 列表工作区

### 页面壳层

用户管理页采用一个连续工作区，而不是“页面中间再放一张厚重卡片”：

- 顶部为标题、说明、总数和主操作。
- 中部为一体化搜索工具栏。
- 下部为有边界但低阴影的表格与分页。
- 共享 `Card` 默认外观不全局改平；用户页通过新的工作台变体使用该结构。

### SearchFilter

新增兼容型 `toolbar` 外观：

- 保留 `fields/values/onChange/onSearch/onReset/extra`。
- 支持左右动作槽或等价布局，使查询与辅助操作不挤在一起。
- 控件统一为 36px 高度。
- 仅文本输入中按 Enter 触发搜索，避免 Select/Popover 内误触发。
- 明确空值协议，避免 `all` 与空字符串互相污染。
- 窄屏允许合理换行，取消不必要的固定最小宽度。

### DataTable

新增兼容型 `workspace`/`compact` 外观：

- 表头使用浅蓝灰底和较弱文字色。
- 表格行约 48–52px；hover 与 selected 使用低饱和浅蓝。
- 表格、空态、加载态和分页属于同一连续 surface。
- 修正 `rowKey=0`、展开按钮可访问名称和操作列表头可配置问题。
- 现有 `columns/data/loading/actions/pagination/renderSubRow` 接口保持兼容。

### Pagination

- 即使只有一页，也可显示总记录数；是否显示页码与记录信息分开控制。
- 使用 button 语义而非无链接地址的 anchor。
- 首页/末页有真实 disabled 状态。
- page size 变化只触发一次清晰的状态更新。
- 桌面显示完整页码，较窄宽度允许换行或简化文案。

### 用户管理页

- 标题改为“用户管理”，说明保持真实业务含义，并显示 `pagination.total`。
- 新增用户按钮仍受 `canCreate('user')` 控制。
- 保留真实搜索、分页、状态切换、编辑、删除、脱敏查看和权限控制。
- 不显示未接入的部门、角色、状态筛选；后续如需增加，应单独接入真实请求参数。
- 用户信息列可组合用户名、真实姓名和次级信息，但手机号、邮箱脱敏按钮必须继续可用。
- 状态仍保留可操作 `Switch`，旁边增加清晰的语义文字；不能用静态 Badge 替代并丢失切换能力。
- 编辑和删除图标按钮补充 `aria-label` 与 `title`。
- 修正搜索/重置使用旧闭包导致请求参数竞态的问题，但不改变 API 契约。

## Dialog 与表单

- Dialog 最大高度为 `85vh`，头部、可滚动 body、底部操作区边界明确。
- 新增/编辑用户表单分为“基本信息”和“组织与权限”两组。
- 宽屏使用两列排布，窄屏退回单列。
- 必填标识、错误信息、辅助信息使用统一样式。
- 角色选择区保持可滚动，避免 Dialog 超出屏幕。
- 取消、Esc、遮罩关闭和提交后的状态与现有行为一致。
- 表单在每次打开或切换用户时恢复正确初始值，避免未提交内容残留。
- 继续执行：编辑时空密码不提交、空部门转 `null`、角色 ID 保持字符串数组、脱敏值过滤、提交中防重复。

## 响应式与可访问性

- 首要验收视口为 1440×900；同时检查 1024×768 和 390×844 的基本可用性。
- 本轮不新增完整移动侧栏抽屉，但不能让页面本身横向溢出；窄屏表格在自身容器内滚动。
- 所有图标按钮有可访问名称。
- 键盘焦点使用主色 ring，不能仅依赖颜色变化。
- Dialog 保持焦点约束、Esc 关闭和关闭后焦点返回。
- 状态色同时配合文字，不能只依赖红绿区分。

## 验证

1. 对目标调用链运行定向 ESLint；项目现有其他页面的历史 lint 错误单独记录，不混入本轮。
2. 运行 `npm run build`，确认 Next.js 生产构建通过。
3. 在隔离的本地前端预览中使用假认证，并仅 mock 必要的只读 GET；中止 POST/PUT/DELETE，避免触碰真实数据。
4. 验证用户列表加载、空态、分页、搜索、重置、状态切换 UI、权限隐藏、删除确认和新增/编辑 Dialog。
5. 分别检查浅色、深色以及默认/蓝色主题组合。
6. 在 1440×900、1024×768、390×844 检查布局。
7. 将选定参考图与实现截图在相同视口并排比较，记录到项目根目录 `design-qa.md`；修复 P0/P1/P2，直到 `final result: passed`。

## 推广策略

用户管理页通过后，再将工作台变体分批迁移到角色、权限、菜单、敏感字段、第三方密钥、API Builder 和监控列表页。每批复用同一套 token 和 composite 组件，不在每个页面复制样式。
