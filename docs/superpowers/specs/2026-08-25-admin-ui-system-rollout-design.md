# Owl 管理平台全站 UI 统一设计

## 目标

将已经在用户管理页确认的高级黑白灰视觉体系覆盖到整个 Owl 管理平台，包括所有登录后页面、登录页、注册页、公开分享页和异常状态页面。改造只调整界面结构、视觉样式和交互反馈，不改变业务流程、接口协议、权限判断或数据逻辑。

## 已确认的设计方向

- 采用“设计系统优先 + 逐页校准”的实施方式。
- 以白色、炭黑和中性灰构成主要界面，避免纯黑压迫感和大面积品牌色。
- 主操作使用炭黑色，次级操作使用白色或浅灰色。
- 绿色、黄色、红色和蓝色只用于成功、警告、危险、信息以及确有业务含义的分类标签。
- 左侧导航保持白色轻量背景，当前项使用浅灰底、炭黑文字和细窄指示条。
- 表单控件默认高度为 40px，聚焦时使用单层边框，不叠加视觉 Ring。
- 保持现有功能、信息密度和页面入口，不进行业务重构。

## 技术边界

- 继续使用 Next.js 16、React 19、Tailwind CSS 4、Radix UI 和现有组件体系。
- 不引入新的 UI 框架、图标库、字体或动画库。
- 继续使用项目内置 Geist 字体。
- 复用现有主题变量，默认主题采用中性配色；其他显式颜色主题继续保留为用户可选项。
- 深色模式必须同步维护，不允许只修复浅色模式。

## 视觉系统

### 颜色

默认浅色主题使用以下角色：

- 页面背景：`#f5f6f8`
- 内容表面：`#ffffff`
- 主文字：`#1f2328`
- 主操作：`#25282d`
- 次级表面与选中背景：`#f1f3f5`
- 常规边框：`#e3e5e8`
- 表单边框：`#d4d7dc`
- 次级文字：`#69707a`

深色主题使用对应的炭黑表面和高对比浅色文字，主操作在深色背景中反转为浅色，保证可读性。成功、警告、危险和信息色必须语义化使用，不得用作普通装饰背景。

### 字体与层级

- 页面主标题使用清晰的半粗体，并配合简短说明文字。
- 卡片标题、表头和表单分组标题使用 500 或 600 字重，避免只靠字号制造层级。
- 数据和时间使用等宽数字特性，减少表格列跳动。
- 说明文字统一使用次级文字色，不使用随意的灰色类名。

### 间距与表面

- 页面外边距由认证布局统一提供，页面内部使用稳定的 16、20、24px 节奏。
- 外层工作区使用 8px 圆角；输入框和按钮使用更紧凑的 6px 圆角。
- 内容表面以细边框和背景差异建立层级，只在浮层、下拉菜单和必要悬浮内容上使用阴影。
- 不使用大面积渐变、装饰纹理或无业务意义的彩色背景。

### 交互状态

- 输入类控件统一为 40px 高度，聚焦时只显示一层炭黑边框。
- 按钮提供 150–200ms 的颜色过渡和轻微按下反馈，不使用夸张缩放。
- 键盘操作仍需有可辨识的焦点状态；输入框采用边框变化，非输入型控件使用克制的焦点指示。
- 加载、空数据、错误和禁用状态必须保持可辨识并与内容形态匹配。

## 组件架构

### 页面框架组件

建立可复用的页面结构组件或等价模式：

- `PageShell`：控制页面最大宽度、垂直节奏和响应式间距。
- `PageHeader`：承载标题、说明、统计补充信息和主要操作。
- `PageToolbar`：承载筛选、搜索、批量操作和视图切换。
- `PageSurface`：承载表格、表单或工作区内容，统一边框、圆角和背景。

这些组件只负责布局和视觉，不接管页面的数据请求或业务状态。

### 基础 UI 组件

统一以下现有组件的默认表现：

- `Button`：主、次、描边、幽灵、危险和文本按钮的层级、尺寸与状态。
- `Input`、`Textarea`、`Select`、日期选择和组合输入：高度、边框、聚焦、禁用与错误状态。
- `Card`：降低默认阴影强度，统一边框、圆角和内容间距。
- `Table`、`DataTable`、`Pagination`：表头、行高、悬浮、操作列、空状态、加载状态和分页区。
- `Tabs`：采用浅灰承载层和中性选中状态，避免大面积黑色选中块。
- `Dialog`、`AlertDialog`、确认弹窗：统一遮罩、尺寸、标题层级、正文间距和底部操作区。
- `Badge`、`Alert`、`Switch`、`Checkbox`、`RadioGroup`：中性默认状态与语义化彩色状态。
- 下拉菜单、Popover、Tooltip 类浮层：统一边框、圆角、阴影和选中状态。

### 页面专用组件

文件管理、API Builder、代码生成器、图表监控和富文本编辑器保留专用结构。它们只复用通用视觉令牌和通用控件，不强行塞入不合适的标准表格或表单模板。

## 页面覆盖

### 常规管理页面

用户、角色、权限、部门、菜单、敏感字段、第三方密钥、API 密钥、邮件模板和日志页面统一为：

1. 页面标题和说明；
2. 右侧主要操作；
3. 筛选或搜索工具栏；
4. 数据工作区；
5. 分页或结果说明。

### 配置页面

系统配置、通知设置、水印设置、仪表盘组件配置和 Zabbix 配置使用清晰的表单分组。保存操作位置保持一致，说明文字靠近对应设置，危险操作与普通设置分离。

### 监控与仪表盘

仪表盘、服务器、API、告警和 Zabbix 监控保留高信息密度。指标数字、趋势、状态和图表容器通过字号、间距和分区建立层级，减少重复的阴影卡片。图表自身颜色属于数据语义，不强制改成单色。

### 复杂工作台

文件管理、API Builder、代码生成器和动态模块页面保留原有交互结构。统一它们的顶部工具栏、面板边界、Tabs、编辑区背景、状态提示、弹窗和空状态，并清理页面内直接使用的蓝色、Slate、Gray 等硬编码视觉样式。

### 登录、注册与公开页面

- 登录和注册使用同一套中性颜色、字体、表单控件和按钮规范，采用适合认证场景的居中布局，不加入装饰性渐变。
- 公开分享页使用统一内容容器、标题、文件或数据状态、错误提示与返回操作。
- 根页面、404 和无权限等异常入口保持品牌一致性，并提供明确的下一步操作。

## 响应式规则

- 桌面端保持后台系统需要的信息密度。
- 页面标题和工具栏在窄屏下垂直排列，主要操作保持可见。
- 表格在无法合理压缩时允许横向滚动，不隐藏关键列来制造伪响应式。
- Dialog 在小屏幕下限制高度并支持内容滚动，操作区保持可触达。
- 登录、注册和公开页面在窄屏下移除不必要外边距，保持表单完整宽度。

## 状态与可访问性

- 所有输入控件必须有可关联标签或无障碍名称。
- 图标按钮必须提供可读的 `aria-label`。
- 键盘焦点必须可辨识，但不得出现边框和 Ring 重叠。
- 删除、停用等危险操作继续使用危险语义色和确认流程。
- 空状态说明当前没有什么数据，并在合适时提供唯一的下一步操作。
- 错误状态使用直接、具体的说明，不使用笼统提示。

## 实施顺序

1. 固化设计令牌和页面结构契约测试。
2. 统一基础 UI 组件。
3. 统一常规管理页和复用度最高的 Dialog。
4. 统一配置类页面。
5. 统一监控、仪表盘和复杂工作台。
6. 统一登录、注册、公开分享和异常页面。
7. 清理残留硬编码视觉样式。
8. 逐页视觉检查并完成完整测试和生产构建。

## 测试与验收

### 自动化验证

- 为页面框架和基础组件补充设计契约测试。
- 通过先失败后实现的方式验证新的组件默认行为。
- 保持现有 48 项 UI 测试持续通过。
- 运行完整 UI 测试、静态检查和 Next.js 生产构建。

### 视觉验收

- 检查所有页面在浅色模式下的标题、工具栏、内容表面和操作层级。
- 抽查各页面组在深色模式下的对比度和语义色。
- 检查所有输入框为 40px，并确认聚焦时没有边框与 Ring 重叠。
- 检查白色侧边栏、当前项浅灰背景和炭黑主按钮在所有后台路由保持一致。
- 检查常见桌面宽度和窄屏宽度下的页面重排。

## 完成标准

- 范围内的页面全部使用统一视觉令牌或语义化状态色，不再依赖无语义的蓝色、Slate、Gray 硬编码作为主要界面样式。
- 常规页面采用一致的标题、工具栏、工作区和分页结构。
- 表单、表格、Dialog、Tabs 和卡片在不同页面中表现一致。
- 登录、注册和公开页面与后台属于同一品牌体系。
- 业务功能、接口和权限行为没有变化。
- 自动化测试、静态检查和生产构建均通过，并完成逐页视觉检查。
